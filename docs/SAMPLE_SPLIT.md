# Sample-count performance split

`bin/split_reference_samples.py --index /absolute/bacteria.sqlite --outdir /absolute/new_output --seed 20261103 --parent-audit /absolute/taxonomy_split_audit.json`

Exact unique sample IDs are sorted, shuffled with Python random.Random(seed), and partitioned globally. The nearest integer 10% (half-up, at least one sample in each group) enters sample10; the rest enters sample90. No sample spans groups, even across different GCFs. Record counts and GCF coverage need not follow 1:9. Sample IDs are the grouping authority; this does not infer patient equivalence between different sample IDs or define a clinical validation design.

Inputs must be complete native schema-3, zero skipped samples, all records selected/eligible, original min-depth0/min-samples1. Other schemas, partial/filtered data and unknown SQL objects are rejected. The optional prior taxonomy audit establishes parent integrity only if its successful output path and SHA match the actual input; without it parent main.quick_check runs. Original index/payloads are preserved, source roots and full-build provenance retained. Existing output directories are refused.

Outputs: two `<input_stem>_{sample10,sample90}.sqlite`, sample_assignment.tsv, sample10.samples.txt, sample90.samples.txt, gcf_group_counts.tsv, sample_split_audit.json and terminal SUCCESS. GCFs lacking group records are omitted from that group. gcf_group_counts.tsv reports missing coverage explicitly. Neither minimum GCF coverage nor balancing/stratification is imposed. Per-GCF counts and depth distributions plus scoped aggregate metadata are recomputed. Original records, IDs, relative payload paths, checksums and query indexes remain exact copies; no numerical payload reconstruction.

Validation: all copied table cells compared against filtered parent rows; sample overlap0, exhaustive sample union and exact record conservation; main.quick_check and main.foreign_key_check on each output; input SHA recheck and output hashes, read-only exclusive publication. quick_check validates SQLite structure without a full index-to-table integrity_check; exact retained-row comparisons and newly built original query indexes provide complementary checks. Parent integrity is inherited from the SHA-matched prior audit when provided. No benchmark speed claim or scientific query follows from creating this split.

Tests cover reproducible/order-independent grouping, rounding, global sample disjointness across GCFs, rare GCF omission/reporting, exact record union, recalculated medians/means, original byte preservation, conflict/filtered input protection, invalid parent receipt and changed-source publication failure. Different seeds can yield the same small partition; tests compare larger fixed fixtures instead of assuming all seeds necessarily differ.

Every SQLite handle is explicitly closed before removing the staging directory. SQLite connection context managers manage transactions, so connection lifetime must be managed separately; this prevents NFS deferred-unlink files from blocking directory cleanup. A regression test checks all tracked handles are closed. Cluster tests also run with TMPDIR on shared storage.
