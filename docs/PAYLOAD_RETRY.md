# Required payload manifests and transient I/O retries

User requested 2026-10-27 after repeated IH/MAG builds failed with missing chunk checksum entries. The seven diagnosed chunk files exist now, storage.json declares them, but both manifests omit them. Directory visibility/cache timing remains a hypothesis; it is not established as the operating-system root cause.

## Builder behavior

Compression futures finish before validation and publication. Geometry inventory, transfer from the temporary candidate, and checksum generation use the explicit storage payload set plus fixed metadata, rather than relying on directory enumeration. Packed chunk names come from storage.json; NPZ and NPY retain their established file names and formats. The outer sample manifest unions declared required files with discovered optional artifacts, so omitted directory entries cannot remove mandatory geometry or native-coverage files from its checksum index. Existing payload schemas, sampling rules and scientific outputs are unchanged.

The builder retries filesystem operations raising ENOENT, ESTALE, EAGAIN, ETIMEDOUT or EIO: at most five attempts per protected operation, with waits of 0.2, 0.5, 1 and 2 seconds (3.7 seconds total sleep, excluding operation runtime). Protected operations include candidate readback/inventory/rename, geometry and sample payload hashing, required-file discovery and final sample validation. PAYLOAD RETRY lines record path, errno, failed attempt and next delay on stderr (sample worker logs). Success requires actual access and SHA computation for every required file. This access-level retry restarts an access/read/hash operation, not extraction or a complete sample build. A separate final-sample retry policy is defined below.

Permission, path escape, empty content, checksum mismatch, malformed/decompression-invalid data and numerical mismatches are not converted to success or retried as transient errors. Exhausted transient errors propagate, preserving FAILED/exit 1 and no outer SUCCESS. Optional artifact discovery and legacy sampled-ID discovery retain existing behavior; no guarantee of perfect enumeration of arbitrary optional artifacts is introduced. Existing reader interfaces and empty status-marker semantics remain compatible.

## Acceptance

Inject directory enumeration that omits every zlib chunk: native build must still produce complete inner and outer manifests, pass strict complete-sample verification, and reload equal aligned mass. Inject repeated ESTALE during candidate reads and ENOENT during outer hashing: recover within the bounded policy. Persistent missing chunks/access must exhaust retries and never publish success. Unit checks cover every retry errno and immediate permission/validation failure. Full native/legacy, packed/NPZ/NPY/auto, empty pools, corrupt payload, query, source identity and restart regression suites must pass locally and on NH at the same commit.

## Existing failed real libraries

This patch does not rewrite old checksums, mark failed attempts successful, change frozen plan identities, or rebuild real inputs. Old plans bind code SHA; do not silently replace V3_20261021 or bypass that guard to resume with changed code. A separately reviewed recovery/deployment step is needed for the seven failed real pairs while preserving healthy results. No old library, original CRAM, shared deployment or active run is modified by this acceptance task.

## Final failed-sample retries (user added 2026-10-27)

For the current native `run --mode local` / `execute --mode local` path (including when this command runs inside an outer scheduler allocation), final collection is followed by at most TWO additional execution rounds for sample–GCF pairs classified FAILED. Thus a repeatedly failing fresh build has one initial attempt plus at most two new attempts per invocation. No extra flag is required. The same jobs/cpus/collect-jobs bounds and immutable source/plan guards apply. Success ends retrying that pair; a healthy pair is never submitted to a retry worker, and its files/progress bytes remain unchanged. A collection-only failure is eligible even if the worker originally exited zero. Every round finishes with full collection/integrity verification. Pending/unknown work is not silently treated as failed work; incomplete catalogs or retry selections that omit unfinished work are rejected. Interruptions propagate and never start another automatic retry round.

Each actual rebuild uses the existing new attempt allocation. Old failed/corrupt attempts remain for diagnosis. Source/FAI changes, genuine persistent corruption/permission failures and locks are not bypassed: retry may fail again, and after the second round the library stays INCOMPLETE with nonzero exit status. No existing checksum is hand-edited or accepted without verification. If strict validation finds an already valid attempt on a selected pair, it may reuse that attempt rather than manufacture another one.

`sample_retries.json` is an operational audit, separate from the scientific plan: `invocations` retain each invocation's start/end, max_additional_attempts=2, per-round selected identities, running/finished/interrupted/failed state and post-collection counts. Final command summary reports sample_retry_rounds, sample_retry_tasks, max_additional_sample_attempts and sample_retry_audit; final local exit-code maps reflect the latest executed outcome. Limits are per explicit invocation; a later manual invocation is a new bounded recovery action. Dry-run advertises the limit but starts no workers. Raw Slurm worker/submission and legacy paths retain their existing explicit recovery behavior; this finalizer does not introduce automatic Slurm resubmission.

Additional acceptance uses real spawned workers and synthetic extraction: a pair fails twice then succeeds on the second retry, another pair stays failed after exactly three attempts, corruption first discovered during collection causes a new verified attempt, and first-pass success causes zero retries. Healthy sample file SHA snapshots remain identical across all collections, old failures remain present, and interruption never begins final retries. No real cohort sample is executed by these tests.
