# Raw CRAM per-query Nextflow v1.1

All user-required legacy query options/outputs are now specified by
RAW_QUERY_PARITY.md; it supersedes the earlier primary-only/minimal-output scope below.

Entry: raw_query/main.nf (independent raw_query/nextflow.config).
One lightweight PLAN, exactly one SCORE process per query, then COLLECT.
Input --index is coverage-raw-cram-index-1, generated by build_cram_index.nf.
Query TSV requires Sample,GCFID,Depth,CramPath. CramPath accepts BAM/CRAM.
BedGraph, Coverage and CRAI columns can remain but are not used for scoring.
Supply --fai_dir (GCFID.fai filenames) or --fai_map
(GCFID/FaiPath or GCF_ID/GCF_path CSV/TSV); full FAI defines the denominator.
No directory scan, reference prebuild, persistent geometry or full-data SHA pass.

## Planning and draws

SQL reads only the requested GCF with ORDER BY Sample,id. Positive CSV Depth
sources are considered; same Sample and canonical query path are excluded.
Repeated paths collapse to the first row. Support requires distinct eligible
reference samples strictly greater than --min_samples (default10).
Low branch is manifest Depth <= --depth_threshold (default5), high is strictly >.
Low planning additionally requires source CSV Depth >= query manifest Depth.
CSV metadata is not claimed equivalent to recalculated legacy geometry statistics.
The actual decoded reference must contain enough aligned mass for sampling;
otherwise all its slots explicitly fail without upsampling, redraw or denominator shrinkage.
Hard-link query aliases are rejected when selected.

N=--reference_draws (default100, >=2) source slots are drawn with replacement using
the prior seed401/key scheme. Each unique selected path is decoded once per query.
Low slots independently sample complete units without replacement within a slot,
using independent draw-ID keyed permutation RNGs until actual query aligned bases
are reached (whole-unit overshoot allowed). Different slots can select the same units.
High slots reuse full aligned/covered window vectors and query similarity once per
unique reference, retaining every repeated source slot in statistics.

--sampling_unit read samples each eligible primary read; fragment groups by exact
QNAME+RG and mate role, preserving actual mate blocks, never intervening span.
Available eligible singleton/unpaired records remain units, as in the original
fragment projection; a missing mate is not invented. Full eligible pairs stay together.
Duplicate primary identities and invalid paired roles fail the source; secondary
and unmapped records are excluded. --min_mapq defaults0.
Supplementary blocks are optional via coverage_alignment_policy, with original
split-read interval checks; see RAW_QUERY_PARITY.md for the full policy interface.
Names/blocks are ephemeral in memory; reference buffers are released between sources.

## Statistics

Reuse query_manifest_stats.similarity, reference_row_means and aggregate unchanged:
GCF natural-contig concatenated windows, aligned-base Pearson, covered-window
Jaccard at --jaccard_coverage_threshold (default0), all N off-diagonal reference
row means, query mean, population SD, stable lower normal tail. This is the v2
reference-distribution rule from the user-pinned17f8fd8 entry, including the high
branch; do not substitute the historical v1 maximum/pair-reservoir rule.
Both p >= alpha -> DETECTED; either FAIL -> NOT_DETECTED; an undefined metric
-> NOT_EVALUATED. Degenerate variance/zero-union/constant Pearson remain explicit.
No calibration or causal interpretation is claimed.

## Failure, output and resume

Each successful query publishes queries/q######## containing summary, draws.tsv,
null.tsv, decode_audit.json, statistics.json, windows and small N-by-window arrays.
Failed query writes the same available diagnostics in its workdir and exits1;
other queries continue. No missing draw is silently replaced. COLLECT joins the
original roster with successful outputs, marking missing receipts ERROR/NO_RECEIPT.
workflow.failOnIgnore makes the overall workflow fail when any SCORE failed.
Thus failed queries cannot be cached as successful; healthy queries can resume.
Collector summaries for missing tasks refer to their original Nextflow logs/workdir.

PLAN is refreshed on every launch. Score cache keys contain content-stable base64
spec values, all selected existing CRAMs, query, FAI, config and staged Python helpers.
Default native file size/mtime cache semantics apply; source bytes must be immutable
(do not preserve timestamps while changing content). Missing inputs are represented
in spec errors so repair changes the key. Planning error affects only its query.
Input changes after planning fail stamp checks. Paths cannot contain pipe/tab/newline
because the task dependency list uses pipe delimiters.
Keep original work directory and launch .nextflow cache for -resume.
No cross-query decode cache, per-source checkpoint or custom cache infrastructure.

## Validation scope

Synthetic read/pair, independent dense selected-ID mass/covered-window oracle,
original scalar null/statistic reconstruction, duplicate-slot decode counts,
high reuse, failures/healthy continuation, native Nextflow resume and repair.
Formal clinical/real CRAM runs remain user-owned. No new scheduler memory/time
requests; Slurm profile queue cpu,tai and executor.queueSize100. CPU is configurable.
