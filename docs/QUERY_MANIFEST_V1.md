# Multi-sample manifest queries (v1)

User-authorized branch `codex/query-manifest-v1`, based on `179a19dea9821bdc2ac28828cf39875ccf8661e9`. Original `Tools.py` and existing query commands are preserved. This is a separate opt-in CLI, not a change to builder/database format or the earlier depth-band policy.

## Optional genome-length detection mode

Use `--detection-config /absolute/path/to/query_detection.json --domain bacteria` or `--domain viral` in place of `--window-size` or `--bin-count`. Choose the matching SQLite index via `--index`. The input TSV and read filters follow the original mode. `--min-samples`, `--jobs`, and the memory options still apply. Depth routing, simulations, reference draws, seed, and null-distribution options belong to the original mode.

Copy and edit [the example JSON](../examples/query_detection.json). The top-level domain keys contain lists of nonoverlapping rules. Each rule specifies `min_genome_bp` (inclusive), `max_genome_bp_exclusive` (exclusive, or `null` for no upper bound), `bin_count`, `distance`, and `max_distance`. Length comes from the full indexed GCF layout. An uncovered length receives `NO_DETECTION_RULE`. A split SQLite index with domain metadata must agree with `--domain`.

Detection profiles use the Bin Count grid's exact number of bins on the virtual genome in indexed contig order. The last bin includes the remainder. Aligned-base mass divided by the actual bin width gives mean depth per bin, then the profile is scaled to sum to 1,000,000. The center is the arithmetic mean of the normalized full-depth profiles for the selected, positive-depth references with the same GCFID. References with the query's Sample or identical source SHA-256 are excluded. The remaining count must be strictly greater than `--min-samples`.

Distance is measured from the full query profile to that center in normalized coverage space. Supported values are `euclidean`, `cosine`, `correlation` (1 − Pearson r), and `jensenshannon` (square root Jensen–Shannon divergence, natural log). A finite distance at or below `max_distance` yields `DETECTED`. A larger distance yields `NOT_DETECTED`. A `null` threshold reports the distance with `THRESHOLD_UNSET`. Unscorable cases, including undefined Pearson, use `NOT_EVALUATED` with a reason in `status`.

The example uses the bacterial Log22 ranges and common bin candidates, and the viral three-stratum baseline candidates. Metric choices illustrate the configuration. All thresholds are unset. Choose thresholds from labeled query-to-center scores with the same domain, interval, bin count, metric and reference cohort. Use participant-independent validation where identities are available. The grid's separation ratios and center-to-center cutpoints describe different observations.

In this mode `summary.tsv` reports the selected rule, distance, threshold, decision and reference counts. Per-query files include `bin_edges.npy`, `query_profile.npy`, `reference_center.npy`, and center membership in `audit.json`. The config file identity is included in the run fingerprint. On NHB use the existing `/home/lianglifeng/01.WorkDir/env/conda-envs/coverage-bin-count/bin/python` runtime, which includes SciPy.

## Original Jaccard/Pearson mode

### Input and scientific definitions

UTF-8 TSV required headers: `Sample`, `GCFID`, `Depth`, `CramPath`. Optional `Coverage`, `CraiPath`, `BedGraphPath` and extra columns are retained in each query audit. Every input row receives stable input-order `query_id`, even repeated Sample/GCF rows. All declared file paths must be absolute, nonempty and readable. CRAI may be blank; no index is created. bedGraph is provenance only: coverage is computed from CRAM CIGAR geometry. Nonempty Coverage requires explicit `--coverage-unit percent|fraction`; no unit inference.

`Depth` is a finite nonnegative supplied manifest value and defines the strict branch `Depth > --depth-threshold` (default 5); equality belongs to low. Actual CRAM depth = eligible aligned-base mass / full database reference length. Both supplied and actual values and their difference are retained; the ACTUAL depth defines low-arm target mass so the original observed CRAM remains the test vector. No disease/covariate information is inferred. A rounded manifest value near 5 can differ from actual depth and therefore route differently; this is visible in audit.

Available references = positive-depth, selected native Sample/GCF records in the SQLite index. Count must be strictly greater than `--min-samples` (default 10). Counts of 10 fail; 11 pass. No nearest/±1X filter and no self exclusion. Sample IDs are source reference identities, not proof of independent patients. Same Sample and same source SHA are flagged on every draw.

Low: `--simulations` (default 100) independent reference SAMPLE draws uniformly WITH replacement. Each draw then independently samples complete eligible units WITHOUT replacement inside that source until actual query aligned-base mass is reached. Target mass is the exact integer query aligned-base count (never a depth/length floating round trip). Last unit stays whole; overshoot/actual depth and ID hash are retained. Insufficient source depth is a recorded draw with no substitution/redraw/upsampling. Missing/corrupt payload is an error. All requested draws remain in denominator; any failed draw invalidates aggregate p (descriptive means/max of finite draws remain clearly labelled).

High: `--reference-draws 100` or `--reference-draws 20%` draws SAMPLE identities WITH replacement. Percentage count is ceil(M% * available). Fixed counts are not capped at available: duplicates carry their original draw weight. Full reference coverage is compared directly to the full query.

Windows (corrected user definition, superseding the earlier per-contig target count): exactly one `--window-size W` or `--bin-count B`. For B, compute the full GCF reference length L=sum(ALL reference contig lengths), then one shared integer width W=ceil(L/B), following the original Tools integer-ceiling convention. The SAME W is then used separately inside each contig. A contig shorter than W contributes one window of its actual length; every terminal remainder is also retained at its actual length. Never derive a different width from each contig, divide B among contigs, bridge boundaries, pad tails or physically concatenate sequence. Missing/zero-covered CRAM header contigs still contribute to the authoritative full GCF length. B is a width divisor, so the actual number of windows after contig splits is not necessarily B. B>L produces 1bp windows.

Example: contigs1800/900/300bp, L3000, B3 -> W1000; actual window lengths1000/800/900/300 (4 windows). For L31/B6, W6 by ceiling. Fixed `--window-size` behavior is unchanged. Window values remain SUM, with short tails naturally contributing less mass under uniform depth. Both query and all references share the same reference order and edges. `windows.tsv` preserves every local coordinate/actual width/shared nominal width; summary/audit add full GCF length, requested B and resolved W. `--windows-per-contig` remains only a deprecated spelling of --bin-count with an explicit CLI warning and the SAME corrected global-GCF semantics; its former per-contig interpretation was a bug. Previous B/N-mode results must not be called equivalent to corrected results; use NEW outputs, and old resume fingerprints are intentionally refused.

Jaccard = intersection/max(union,1), binary coverage>0; common zeros retained, double-zero J=0 with explicit descriptive-zero-union state. Pearson = centered dot/(norm product+1e-12), signed and ordered, common zeros included. Constants or single windows have null R and status (not original's numeric zero). Low test statistic = mean query-vs-simulation. Null = each simulation's mean similarity to all other draws. Actual diagonal is excluded rather than subtracting an assumed 1; this avoids epsilon/constant diagonal artifacts. Population SD, lower normal CDF reproduce Tools z for nondegenerate data. Zero SD/nonfinite/too little evidence => p blank and status. N internal draws are ONE test, no per-draw q or automatic FDR. No p against Pearson R=0, no claim that p>=alpha proves consistency, and no calibrated/clinical claim.

High test statistic = MAX query-vs-draw, like Tools. On 2026-10-25 the user explicitly selected the high-depth null: unordered pairs from the CURRENTLY DRAWN references with DIFFERENT Sample identities. Repeated draws retain multiplicity across pairs to other samples; same-Sample pairs are excluded. `--high-null draw-pairs` is now DEFAULT. Uniform reservoir sampling without replacement selects min(candidate pairs, `--null-limit`) pairs, with a hard allowed limit of 1..1000 (default1000). The SAME selected pairs serve both metrics; seeds are independent of reference-sample and read-unit RNG streams. This defines the formerly external Tools reference distribution for this workflow; it is user specified, not claimed to have been implicit in original Tools.

The aggregate maximum is tested against the per-metric selected-pair values using population SD and lower normal CDF. All equal reference values have exact SD0, including repeated floating values whose naive NumPy SD can be nonzero through rounding. Zero variance, nonfinite Pearson/constant windows or too few eligible pairs retain explicit non-estimable p, never forced 0/1. `--high-null none` remains an explicit descriptive-only replay option, not the default. No claim of statistical calibration follows from specifying the null.

## Output, audit, continuation

`summary.tsv`: exactly one row per input, stable order, overall/draw/metric status, supplied/actual depth and coverage, available/requested/valid/unique/duplicate counts, means and maxima, primary mean(low)/max(high), raw p and null count/mean/population SD; high-null candidate-pair and sampled-pair counts. No fabricated I/U for an aggregate.

`queries/q########/`: original input row and measured wall/user/system/cumulative per-process peak RSS/cache/stage statistics in audit.json, summary.json, windows.tsv, query_windows.npy, reference_windows.npy (int64 WINDOW sums, not per-base), deterministic compressed draws.tsv.gz and null.tsv.gz, checksum ledger. All draw/source/replicate identities, same-source flags, requested/actual depth, units, ID/RNG hashes and per-pair I/U/J/R are retained. High null table additionally retains left/right reference Sample/ID and pair I/U, with draw IDs linking all source identities in draws.tsv.gz. Low null table saves each simulation row mean; full window vectors permit independent reconstruction. Failed draw matrix rows are zeros only as storage placeholders, and are always excluded via draw status; they are NEVER evidence for zero coverage. Query errors retain status and original row/traceback; an error may have partial intermediates and is never marked successful.

`run.json`: complete configuration, manifest full SHA/stat, SQLite full SHA/stat and metadata, source Python-file SHAs. `completion.json`: terminal state, denominator, wall/user/system CPU, controller peak RSS, output byte count and summary SHA. Per-query peak RSS is process cumulative, not additive across queries. Completion wall/CPU include preflight hashing; process launch/interpreter costs require an external time measurement. Output byte count is measured before writing completion.json (explicit scope, not total final directory size).

Output directory must be new. Directory-exclusive run lock prevents concurrent writers. Query results publish by rename only after their ledger is written; root summary publishes by atomic file replace. `--resume` requires identical configuration, code and manifest/database bytes AND stat, verifies saved query payload hashes and previously read source identities, reuses complete per-query results, and processes missing queries. Terminal error rows are reused rather than automatically retried. A hard interruption may leave hidden temporary directories and a lock; inspect process ownership before manually removing a stale lock. No automatic cleanup can delete another run. Use a new output directory to rerun failed rows or change jobs/parameters. Resume with different jobs is intentionally refused, although a NEW run at different jobs reproduces science.

SQLite opens mode=ro/query_only with one read transaction per GCF worker, indexed GCF candidate lookup. No worker loads total-database payload. Groups run across processes under ONE jobs budget, BLAS/OMP threads fixed to 1. A GCF's query rows remain together to reuse reference geometry/full windows. Single-GCF workloads use one worker; no within-GCF parallel scaling claim. `--cache-mib` total accounted LRU budget divides by jobs; `--work-mib` separately bounds 3x numeric window matrix payload per worker. Both default to 131072 MiB (128 GiB) each, as requested on 2026-10-29. In this CLI, zero independently means unlimited: `--cache-mib 0` retains cache entries without budget eviction, and `--work-mib 0` skips the numeric matrix budget check. Negative values are rejected. Positive values retain the same division and guards, even if division yields zero bytes. Unlimited effective byte budgets are recorded as JSON null in run/audit metadata, while the requested MiB values remain 0. Cache stamp/hash validation and close/cleanup still apply. Other native query commands keep their existing zero-cache behavior; the internal unlimited cache sentinel is None. Changing code or budgets still invalidates existing resume fingerprints; use a new output directory for changed runs. These are not hard RSS caps: Python objects, query/reference geometry, decompression and sampling scratch are additional. Too-large window matrices fail explicitly. Native matching windows are verified/read directly (no geometry decompression); other windows and low simulations load validated geometry. Used payload hashes and reference file/status stamps are checked; this does not claim a full re-audit of every unused database payload.

No performance speedup is claimed relative to original Tools. Timings characterize only the measured workload. Original Tools is the required primary baseline for any future acceleration claim.
